# Домашнее задание к занятию «Введение в микросервисы», Марченко Николай

## Задача

Руководство крупного интернет-магазина, у которого постоянно растёт пользовательская база и количество заказов, рассматривает возможность переделки своей внутренней   ИТ-системы на основе микросервисов. 

Вас пригласили в качестве консультанта для оценки целесообразности перехода на микросервисную архитектуру. 

Опишите, какие выгоды может получить компания от перехода на микросервисную архитектуру и какие проблемы нужно решить в первую очередь.



## Решение задачи

#### Выгоды для компании:

    Масштабируемость — можно масштабировать только нагруженные сервисы (например, «Корзина» или «Оплата»), а не всё приложение целиком.

    Скорость разработки — команды работают независимо над своими сервисами, используют разные технологии и языки, быстрее выпускают новые функции.

    Отказоустойчивость — падение одного сервиса (например, «Отзывы») не роняет весь магазин.

    Легче внедрять изменения — не нужно пересобирать монолит, достаточно обновить один микросервис.

    Гибкость найма — можно нанимать специалистов под конкретные задачи (Python, Go, Java и т.д.).


#### Проблемы, которые нужно решить в первую очередь:

    Сетевые задержки и надёжность — сервисы общаются по HTTP/gRPC, нужны таймауты, ретраи, Circuit Breaker.

    Распределённые транзакции — заказ, оплата, склад — сложно гарантировать согласованность данных (нужен Saga или Event Sourcing).

    Мониторинг и трассировка — без единого лога и трейсинга (Jaeger/Zipkin) невозможно понять, где упал запрос.

    DevOps-инфраструктура — нужны контейнеризация (Docker), оркестрация (Kubernetes), CI/CD, Service Discovery.

    Безопасность — аутентификация и авторизация между сервисами (JWT, OAuth2, API Gateway).

    Культура и команды — переход требует дисциплины, чётких контрактов API и владения каждым сервисом отдельной командой.


Итог: переход выгоден при росте нагрузки и команды, но требует серьёзных вложений в инфраструктуру и организацию процессов. Начинать стоит с одного-двух сервисов, а не переписывать всё сразу.
